# 칸 사실표 — 견적서·거래명세서·청구서

근거 표시: **(법)** 법령 조문(2차 확인 — 법령 재게시·세무 해설 페이지로 확인, 국가법령정보센터 원문은 조회 과부하로 못 엶) · **(관행)** 법정 서식·필수 칸 근거를 찾지 못한 민간 관행 · **(우리)** 이 방법이 고른 기본값(근거가 아님, 사람·전 서식이 이긴다).
조사일 2026-10-26. 바깥 근거 원본: 티파이브 연구 `결과물품질-스킬연구-20261026/_자료/A-바깥자료-한국형-20261026.md` 2-2절.

- 날짜는 `2026-10-26`·`2026.10.26`·`2026. 10. 26.` 모두 받고 `2026. 10. 26.` 로 적는다. 날짜로 못 읽으면 그대로 두고 `warnings` 에 적는다.
- `tax` 를 빼면 과세. 면세·영세 품목은 세액 0, 세액 칸에 「면세」·「영세」로 보인다.
- 엑셀 틀은 세액을 품목마다 낸다(`vatBasis: line`). 합계에서 한 번 내는 꼴이 필요하면 워드로 만든다.

## 2. 칸 — 무엇이 꼭 있어야 하나

스크립트는 「필수」가 비면 「(미정)」으로 적고 `missing` 에, 「권장」이 비면 `warnings` 에 올린다.

**견적서·거래명세서·청구서의 법정 서식이나 법정 필수 칸은 확인 안 됨**(조사에서 근거 문서를 찾지 못함). 위 「필수」는 세금계산서 기재사항을 빌려 온 관행이고, 사람이 쓰던 서식과 다르면 그 서식이 이긴다.

## 3. 계산 규칙 (`forms.mjs`)

| 규칙 | 값 | 근거 |
|---|---|---|
| 세액 | 과세 품목 공급가액 × 10% | 부가가치세법 제30조 세율 10% — 널리 알려진 값, 이번 조사에서 조문 원문은 확인 안 함 |
| 끝수 | 원 미만 버림(`floor`), `round`·`ceil` 고를 수 있음 | (우리) — 법정 끝수 규칙 확인 안 됨 |
| 세액 기준 | 품목마다 끝수 처리 뒤 합(`line`), 또는 공급가액 합계에서 한 번(`total`) | (우리) — 두 값이 다르면 `warnings` 에 둘 다 적음 |
| 부가세 포함 단가 | 세액 = 포함 금액 ÷ 11(끝수 처리), 공급가액 = 포함 금액 − 세액 | (우리) — 관행 여럿, 기준 확인 안 됨 |
| 합계 | 공급가액 + 세액 | 정의 |
| 한글 금액 | 네 자리씩 만·억·조, 자리마다 「일」까지(일십·일백), 띄우지 않음 | (관행) |
| 사업자등록번호 | 10자리, 가중치 1·3·7·1·3·7·1·3·5 검증 숫자 | 널리 쓰이는 검증 식 — 국세청 원문 확인 안 됨. 떨어져도 막지 않고 「확인 필요」 |

## 4. 세금계산서와의 경계

- **발급은 하지 않는다.** 전자세금계산서 발급·전송은 홈택스 길(티파이브 2.3 E1)이 맡는다.
- 사람이 「세금계산서로」라고 하면, 필요적 기재사항 4칸(부가가치세법 제32조 제1항, 2차 확인)이 사실표에 다 있는지만 알린다: ① 공급자 등록번호와 성명 또는 명칭 ② 공급받는 자 등록번호 ③ 공급가액과 부가가치세액 ④ 작성 연월일. 빠지면 매입세액 불공제·가산세 위험이 있다는 해설(2차)이 있다.
- 시행규칙 별지 서식 번호·원문은 확인 안 됨.
