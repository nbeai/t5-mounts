# 상세 페이지 만들기

상세 페이지는 사진을 예쁘게 늘어놓는 것이 아니라, 처음 온 손님이 위에서 아래로 내리며 「사도 되겠다」에 이르게 하는 판매 이야기다.
사람의 말·브랜드 자료·「내 방식」이 있으면 그것이 먼저다. 아래는 그 위에서 쓰는 원리다.

## 1. 카피 계획이 먼저다

- 이미지를 그리기 전에 계획을 쓴다: 상품 파악(무엇·누구에게·왜 지금) → 섹션 표(번호·역할·헤드라인·본문 한두 줄·쓸 사진이나 그림). 계획은 대화 폴더에 `<상품> 상세 페이지 계획.md` 로 먼저 저장하고, 답에도 표로 보여 준다.
- 섹션 수는 정해진 숫자가 아니라 상품에 맞게(대개 8~12). 흔한 흐름: 첫 장(약속 한 줄 + 대표 사진) → 공감(이런 고민) → 해결(이 상품) → 특징 3~4개(장마다 하나) → 사용 장면 → 구성·규격 → 후기(있을 때) → 자주 묻는 질문 → 구매 안내.
- 계획을 보여 준 같은 차례에 첫 판까지 만들어 보여 준다. 사람이 「3번 문구 바꿔 줘」, 「후기 섹션 하나 더」 하면 그 섹션만 고친다.

## 2. 재료의 사실만 쓴다

- 사진·말·첨부에서 사실표를 먼저 만든다: 알려진 값(가격·용량·성분·원산지·배송·기간·후기 원문), 계산한 값(할인가·묶음가 — 식을 답에 한 줄), 모르는 값.
- 성분·효능·인증·수상·판매량·후기는 재료에 있는 것만 쓴다. 모르는 값은 섹션에서 빼고 답에서 「○○를 알려 주시면 넣을게요」로 한 줄 묻는다(그 칸 없이 끝까지 만든다).
- 후기: 사람이 준 실제 후기가 있으면 고르고 다듬지 않고 옮긴다(맞춤법만). 없으면 후기 섹션을 빼거나, 넣어 달라고 하면 장 위에 「예시 후기」라고 분명히 적는다.

## 3. 만드는 길 — 원본 사진 + 글자 층(기본)

- carousel_editor 의 한 프로젝트가 상세 페이지 하나다. size 는 상세 페이지 폭 860 기준 `860x1200`(긴 섹션이 많으면 `860x1600`). 한 프로젝트의 장은 같은 크기다.
- 섹션 = 장 하나. 사진 섹션은 원본 사진(사람이 준 것, 필요하면 photo_editor 로 보정·배경 제거) 위에 블록 글자, 사진 없는 섹션은 html 장으로 그린다(특징 아이콘·비교 표·단계·구성 그림·자주 묻는 질문 카드).
- 글자는 이미지 안에 그리지 않고 글자 층으로 얹는다: 한글이 렌더 글자라 오타·깨짐이 없고, 문구 수정에 이미지 다시 만들기가 없다.
- 장마다 눈이 먼저 닿는 것 하나를 더한다(캐러셀 5-1 과 같다): 사진, 큰 숫자, 나란한 카드, 아이콘 줄, 비교 표, 체크 목록. 글을 줄여 깔끔해 보이게 하는 것은 품질이 아니다.
- 색: 사람·브랜드 색이 없으면 `${CLAUDE_SKILL_DIR}/../color-system/data/presets.json` 에서 업종·목적 조합 하나를 골라 그 역할 값(bg·surface·accent·text)을 theme 과 html 장에 그대로 쓰고, 답에 조합 이름을 한 줄 적는다.
- 사람이 「첫 장에 모델 넣어 줘」처럼 없는 사진을 원하면 이미지 만들기 손(media)을 쓴다. 이때 비용·연결은 그 손의 사실을 따르고, 만든 사진임을 답에 밝힌다.

## 4. 고치기 — 그 섹션만

- 문구·사진 하나 고치기: slidePatch(index)로 그 장만. 섹션 더하기 insert, 복사 duplicate, 빼기 removeIndex, 순서 move. 다른 섹션은 다시 만들지 않는다.
- 사람이 패널에서 손으로 고친 값(show 로 보임)은 지킨다. 고친 뒤 완성본 한 장도 다시 잇는다(5).

## 5. 완성본 한 장과 섹션별 파일

- 섹션 PNG 는 carousel_editor 가 「<제목> 01.png …」로 저장한다. 완성본은 그 순서대로 세로로 잇는다: 관리 명령 ffmpeg(없으면 cli_prepare 로 붙인다)로
  `ffmpeg -y -i "<제목> 01.png" -i "<제목> 02.png" … -filter_complex "vstack=inputs=N" "<제목> 완성본.png"` — 같은 폭이라 그대로 이어진다.
- 결과로 고르는 순서: 완성본 한 장 → 섹션 파일들 → 계획 파일. 답에는 섹션 표(바뀐 섹션 표시)와 완성본을 먼저 보여 준다.
- 올리는 곳(스마트스토어·자사몰)의 이미지 한 장 높이 제한이 있으면 그 높이로 나눈 파일도 함께 낸다(같은 ffmpeg crop).

## 6. 끝내기 전 확인

- 밀착 인화지와 완성본을 위에서 아래로 손님 눈으로 본다: 첫 장이 무엇을 파는지 3초 안에 보이나, 섹션마다 하나의 생각인가, 같은 사진이 반복되나, 글이 넘치나.
- 섹션 글의 숫자·이름·후기를 사실표와 한 번 맞춰 본다.

### 현재 결과판의 확인
사용자 목적과 현재 편집판/선택 레퍼런스의 원리를 필요한 범위만 적용한다. 이미 읽은 방법을 다시 열거나 국소 수정에 전체 조사를 반복하지 않는다. 기존 제작·내용·렌더 검사의 이름/범위/근거를 전달할 attachment/family/판/SHA와 결속한다(프로젝트·렌더판이 있으면 함께). 같은 바이트의 유효 검수는 재사용하고, 바뀐 부분은 확인을 갱신한다. 모델의 체크리스트·일반 파일 등록·기계 검사·사람의 품질 평가는 서로 대신하지 않는다. 원본과 승인된 부분은 보존하며 확인하지 못한 범위는 미측정으로 남긴다.
