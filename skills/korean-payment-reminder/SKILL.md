# 받을 돈 독촉 문서

독촉은 세 걸음이다: **정중한 메시지 → 내 이름으로 보내는 내용증명 → 지급명령**. 이 방법은 걸음마다 쓸 글과 사실을 준비하고, 지급명령은 **자료표와 공식 길 안내에서 멈춘다**.
아래는 규칙이 아니라 원리다. 사람의 말·「내 방식」·그 거래처와의 관계가 먼저다. 이 방법은 **사장님이 자기 돈을 받으려고 자기 이름으로 쓰는 문서**를 돕는다. 남의 채권을 대신 받아 주는 일로 말하지 않으며, 법률 판단을 하지 않는다([references/boundary.md](references/boundary.md)).

## 0. 사실표 — 금액은 한 곳에서

받을 돈 사실은 장부의 「받을 돈」 표가 있으면 그것이 먼저, 없으면 사람이 준 견적·계약·거래명세·청구 자료에서 모은다. `"$TMPDIR"/미수.json` 에 쓴다(꼴은 [references/facts-format.md](references/facts-format.md)). 금액·날짜·약속은 자료에 있는 것만 쓰고, 증거 파일 이름(`docs`·`evidence`)을 함께 적는다.

```bash
node "${CLAUDE_SKILL_DIR}/scripts/reminder.mjs" summary --facts "$TMPDIR/미수.json" --evidence "증거 폴더"
```

청구 합계·받은 돈·남은 금액(한글 금액 포함)·원래 기한에서 지난 날수, 증거 파일이 폴더에 있는지(`missing`)·사실표에 없는 파일(`notListed`)이 나온다. 이자·지연손해금은 계산하지 않는다. 계약서에 약정 이자가 있으면 그 문구를 인용만 한다.

끝 조건: 남은 금액이 자료와 맞고, 증거 파일이 다 있거나 빠진 것을 사람에게 알렸다.

## 1. 독촉 메시지 (1~3차)

말투만 단계별로 다르게 쓴다(꼴은 [references/message-steps.md](references/message-steps.md)). 금액·기한·계좌는 `summary` 값 그대로, 사장님 이름으로. 쓴 글은 판단·위협처럼 읽히는 말이 있는지 본다.

```bash
node "${CLAUDE_SKILL_DIR}/scripts/reminder.mjs" lint --input "$TMPDIR/독촉1.md"
```

후보가 나오면 문맥을 보고 사실 문장으로 바꾼다(「법적 조치를 하겠습니다」 → 「기한이 지나면 다음 절차를 알아보겠습니다」). 보내기는 사람이 한다.

## 2. 내용증명 초안

본문(인사·거래 경위·요청)을 `"$TMPDIR"/본문.md` 에 쓰고(문단은 빈 줄로 나눔), 당사자·거래 표·남은 금액·기한·계좌는 스크립트가 사실표에서 채운다.

```bash
node "${CLAUDE_SKILL_DIR}/scripts/reminder.mjs" letter --facts "$TMPDIR/미수.json" --body "$TMPDIR/본문.md" --out "$TMPDIR/내용증명.json"
"$T5_DOCUMENT_CLI" create-docx --spec "$TMPDIR/내용증명.json" --output "내용증명_가나다_20261026.docx"
```

출력의 `missing`(빈 칸)과 `lint`(판단처럼 읽히는 말)를 0으로 만든 뒤 넘긴다. 발송은 사람이 인터넷우체국이나 우체국 창구에서 한다(안내는 [references/official-paths.md](references/official-paths.md)).

## 3. 지급명령 자료표 — 여기서 멈춤

```bash
node "${CLAUDE_SKILL_DIR}/scripts/reminder.mjs" claim-sheet --facts "$TMPDIR/미수.json" --evidence "증거 폴더" --out "$TMPDIR/자료표.json"
"$T5_DOCUMENT_CLI" create-docx --spec "$TMPDIR/자료표.json" --output "지급명령_자료표_가나다.docx"
```

당사자, 청구·받은·남은 금액, 있었던 일(날짜순), 증거 파일과 폴더에 있는지를 한 문서로 묶는다. **신청서 칸 초안은 만들지 않는다.** 신청·비용 납부는 사람이 전자소송에서 한다.

## 4. 답

남은 금액, 만든 파일(메시지·내용증명·자료표), 빠진 증거, `lint` 에서 고친 것, 다음 걸음의 공식 길을 적는다. 「이길 수 있나요」 같은 질문에는 판단하지 않고 법률 상담(대한법률구조공단 등)을 권한다.

### 현재 결과판의 확인
사용자 목적과 현재 편집판/선택 레퍼런스의 원리를 필요한 범위만 적용한다. 이미 읽은 방법을 다시 열거나 국소 수정에 전체 조사를 반복하지 않는다. 기존 제작·내용·렌더 검사의 이름/범위/근거를 전달할 attachment/family/판/SHA와 결속한다(프로젝트·렌더판이 있으면 함께). 같은 바이트의 유효 검수는 재사용하고, 바뀐 부분은 확인을 갱신한다. 모델의 체크리스트·일반 파일 등록·기계 검사·사람의 품질 평가는 서로 대신하지 않는다. 원본과 승인된 부분은 보존하며 확인하지 못한 범위는 미측정으로 남긴다.
