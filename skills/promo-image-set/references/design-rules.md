# 배치·크기·색 기준

## 판과 좌표

- 한 장 HTML에 세로판 `.P`(1080×1350)와 가로판 `.L`(1920×1080)을 함께 둔다. 요소는 `position:absolute`로 놓되 좌표는 판마다 따로 준다. 같은 좌표를 두 판에 쓰면 반드시 겹친다.
- 여백: 세로 좌우 72px, 가로 좌우 96px. 위 머리줄(로고+명칭 왼쪽, 주제 오른쪽), 아래 오른쪽에 주소. 내용은 세로 1280px, 가로 1000px 안에서 끝낸다.
- 세로판: 위에 글, 아래에 증거 그림. 가로판: 왼쪽 글(폭 700~800px), 오른쪽 증거 그림. 가로판은 오른쪽에 몰고 왼쪽 아래를 비우기 쉬우니, 남는 왼쪽 아래에는 요청 말풍선이나 짧은 증거 한 줄을 둔다.

## 글자 크기 (휴대폰 피드에서 읽히는 최소)

| 요소 | 세로판 | 가로판 |
|---|---|---|
| 큰 제목 | 80~98px, 굵기 800, 자간 -0.045em | 84~104px |
| 부제 | 32~33px | 32px |
| 카드 제목 | 24px 이상 | 22px 이상 |
| 카드 보조문구 | 20px 이상 | 19px 이상 |
| 각주(조건·예시 표기) | 17~19px — 휴대폰에서는 안 읽힌다고 보고, 꼭 필요한 조건만 |

세로판을 폭 390px로 줄이면 원본 20px 미만은 사실상 사라진다. 증거를 화면 캡처 속 작은 글자에 맡기지 말고, 핵심 숫자·문장은 HTML 글자로 다시 크게 쓴다.

글꼴은 시스템 한글 고딕(맥 `Apple SD Gothic Neo`, 윈도우 `Malgun Gothic`)을 쓴다. `templates/base.css`에 둘 다 들어 있다. 웹 글꼴을 내려받지 않아도 된다. 책·문학 느낌의 장면에만 명조.

## 색

- 바탕 미색(#F5F2EB 계열) + 흰 카드 + 검정 글자 + 브랜드 강조색 한 가지. 강조는 제목 둘째 줄 한 곳.
- 시리즈가 단조로우면 표지·마무리 한두 장만 바탕을 바꾼다. 진한 바탕이 「너무 파랗다/어둡다」는 말을 들으면 밝은 바탕에 선 구분·큰 여백으로 바꾼다(표지를 카드 없이 선으로 나누면 깔끔해진다).
- 카드 그림자는 연하게 한 종류. 흰 카드·큰 그림자·둥근 칩을 모든 장에 반복하면 템플릿 티가 난다 — 표지·정리 장은 카드 대신 선과 여백.

## 증거 그림

- 실제 화면은 결과가 보이는 부분만 크게 자른다. 제목 줄의 버그처럼 보이는 문구(「금액 단위 미표기」 등), 옛 로고, 모델·계정 이름, 개인정보는 잘라 낸다.
- 표가 보이는 그림은 데이터 행이 최소 3행 보이게 자른다(머리행만 보이면 증거가 없다).
- `object-fit:cover`로 세로 9:16 결과물을 좁은 칸에 넣으면 글자가 잘린다. 칸을 `aspect-ratio`로 원본 비율에 맞추거나, 글자가 왼쪽 정렬이면 `object-position:left`.
- 직접 그린 틀(브라우저·메신저·휴대폰·책) 안의 회색 줄(스켈레톤)은 와이어프레임처럼 보인다 — 실제 문장 두세 줄로 채운다.
- 실제 화면과 직접 그린 그림이 섞이면 각주에 「설명용 예시」를 적는다.

## 캐릭터

- 원본 PNG를 비율 유지로 줄여 쓴다(얼굴 윤곽·눈 위치·색감을 바꾸지 않는다). 새 표정이 필요하면 원본을 참조로 생성하고 요청문을 `generation-prompts.json`에 남긴다.
- 화면 끝에서 잘리지 않게, 글자·카드 핵심을 가리지 않게 둔다. 카드 모서리에 살짝 걸치는 정도까지.

## 자주 난 결함 (찍을 때마다 확인)

1. 판끼리 좌표 공유로 겹침 — 세로판 부제와 그림, 가로판 태그 줄과 카드.
2. 화면 밖 잘림 — 오른쪽 끝 캐릭터, 넓게 잡은 영상 칸.
3. 빈 증거 — 표 머리행만, 숫자가 칸 아래에서 반쯤 잘림.
4. 줄바꿈 — 가운뎃점·조사가 줄 끝/줄 앞에 매달림(「4개 / 중」), 낫표 뒤 띄어쓰기 빠짐.
5. 말투 섞임 — 합니다체와 해요체, 마침표 있는 말풍선과 없는 말풍선.
6. 같은 정보 두 번 — 칸 이름과 아래 체크리스트가 같은 말.
7. 문법 — 「나는 깊이 아는」처럼 주어가 꼬인 제목. 소리 내 읽어 본다.
8. 숫자 앞뒤 안 맞음 — 합계 칸과 행의 합, 「세로·가로 두 벌」이라 써 놓고 둘 다 세로인 그림처럼, 글이 주장하는 것과 그림이 보여 주는 것이 어긋난다. 그림 속 숫자는 더해 본다.
9. 화면 캡처의 찌꺼기 — 패널 사이 넘김 화살표·스크롤 막대·잘린 단추. 자르는 경계를 손잡이 바깥으로 10~20px 옮긴다.
10. 표기 섞임 — 시각(「오전 9:00」과 「14:10」), 띄어쓰기(「돌려드려요」와 「알려 드려요」), 가운뎃점 앞뒤 칸. 본문·칩은 붙인 가운뎃점(·), 해요체 보조용언은 띄어 쓴다(「드려요」 앞 띄움).
11. 위·아래가 잘린 그림 — 헤드리스 크롬을 `--window-size`·`--screenshot`로 찍으면 실제 화면 높이가 창보다 작아(맥에서 87px) 아래가 잘리고, 이를 이미지 프로그램으로 자르면 가운데 기준으로 잘려 위도 잘린다. `scripts/render.mjs`는 DevTools 프로토콜로 화면 크기를 정확히 지정해 찍으니 이 스크립트를 쓴다. 다른 방법으로 찍었다면 머리줄이 CSS의 `top` 값 자리에 있는지 확인한다.
