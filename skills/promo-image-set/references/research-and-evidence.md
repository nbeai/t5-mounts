# 레퍼런스 조사와 근거표

## 레퍼런스 조사 — 곳마다 적을 것

| 칸 | 적는 것 |
|---|---|
| 곳·출처 | 제품명, URL, 확인 날짜, 확인 방법(직접 열람 / 검색 요약 / 못 엶과 이유) |
| 후킹 | 첫 줄이 시선을 잡는 구조(질문형·전후 대비·결과 선언 등). 인용은 15단어 미만 한 줄까지 |
| 정보 밀도 | 한 장의 메시지 수 |
| 위계·여백 | 제목/본문 크기 대비, 강조색 개수, 여백 |
| 실제 화면 | 화면을 크게 한 장 / 잘라서 / 주석·말풍선이 화면 밖으로 넘어오는지 |
| 캐릭터·그림 | 장식인지, 일하는 동작인지 |

## 지금까지 쌓인 원칙 (가져올 것)

1. 한 장 한 메시지. 제목 하나가 그 장의 전부.
2. 행동과 결과를 묶은 큰 제목(「~만 하면 ~끝나요」).
3. 사용자가 실제로 칠 요청 문장을 말풍선으로.
4. 과정보다 끝난 결과 화면 하나를 크게.
5. 제품 화면은 크게 잘라 쓰고, 말풍선·라벨이 화면 테두리 밖으로 넘어오게.
6. 전후 대비 숫자는 근거가 있을 때만.
7. 캐릭터는 소품과 동작으로 맡은 일을 보여 준다.
8. 굵은 검정 제목 + 회색 본문, 강조색은 한 장에 한 곳.
9. 해요체, 의미 단위 줄바꿈.

## 피할 것

그라데이션 광채·유리 질감, 「혁신적인」 같은 빈 형용사, 아이콘만 늘어놓기, 업계 용어(사용자 대상이면 MCP·API 같은 말은 괄호 보조로만), 반짝이·로봇 같은 상투적 AI 그림, 근거 없는 숫자, 줄여서 글씨가 안 읽히는 화면 캡처, 전형적인 AI 생성 인물 사진(긴 생머리 측면 인물 등 — 제품 컷으로 바꾼다).

## 근거표 — 장마다

```
## NN 주제 — `sNN-이름`
핵심 문구: **…**

| 주장 | 근거 |
|---|---|
| 이미지에 쓴 주장 그대로 | 파일:줄 「짧은 원문」 / 실사용 기록: 대화 제목·게시 링크 확인 |
```

판정 기준:
- **확인** — 실제 결과물·실사용 기록, 또는 설명서·제품 정의에 그대로 있음.
- **부분** — 조건·제약이 크거나 일부 경로만 됨. 이미지에는 조건을 작은 글씨로 함께 쓴다(예: 「평소 크롬에 로그인된 계정으로」, 「생성 서비스 연결이 필요해요」).
- **근거없음** — 이미지에서 뺀다. 사람이 원한 주제라도 빼고, 빠졌다고 보고한다.

실사용 기록(지난 대화·결과 파일)을 근거로 쓸 때는 고치지 않고 읽어서, 최종 답의 성공 문장과 링크·결과 파일 경로를 함께 적는다. 실패·대기로 끝난 기록은 근거로 쓰지 않는다.

「근거가 약하거나 애매한 주장」 목록에는 다음을 늘 점검한다: 설명서와 실사용 기록이 어긋나는 것, 설명서끼리 어긋나는 것, 다른 회사 브랜드·실존 인물이 보이는 그림, 사람 본인 얼굴, 효과 숫자.
