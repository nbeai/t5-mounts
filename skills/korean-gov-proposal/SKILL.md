# 정부지원사업 사업계획서

심사위원은 정해진 양식에서 평가 항목마다 근거를 찾는다. 그래서 이 일은 글을 잘 쓰는 일이기 전에 **받은 양식의 칸을 공고의 규칙대로 빈틈없이 채우는 일**이다.
아래는 규칙이 아니라 원리다. 사람의 말·「내 방식」이 먼저고, 그다음이 **지금 받은 공고문과 양식**이다. 공고마다 목차·쪽수·가리기 규칙이 바뀌므로 이 방법은 특정 연도 양식이나 숫자를 싣지 않는다 — 늘 그 공고를 읽어 맞춘다.

## 0. 받을 것

공고문, 그 공고의 사업계획서 양식 파일, 사업 자료. 양식이 없으면 「공고 페이지의 사업계획서 양식 파일을 붙여 주세요」라고 한 번 묻는다. 양식 없이 목차를 지어 새 문서를 만들지 않는다. 원본 양식은 고치지 않고 사본(`--output`)에 채운다.

끝 조건: 공고문과 양식 파일이 있고 결과 파일 이름이 정해졌다.

## 1. 양식 읽기 — 칸 지도

```bash
"$T5_DOCUMENT_CLI" read-hwp "양식.hwpx" > "$TMPDIR/양식.json"
node "${CLAUDE_SKILL_DIR}/scripts/proposal.mjs" map --input "$TMPDIR/양식.json"
```

DOCX 양식은 `"$T5_DOCUMENT_CLI" inspect` 결과를 같은 스크립트에 넘긴다. 출력은 목차, PSST 네 제목의 자리, 안내 문구로 보이는 줄(※·작성 요령 등), 자리표시(○○○·OOO), 빈 표 칸, `formLabels`(이름표 옆 빈칸), 글자 수다. 이것으로 **칸 지도**를 만든다: 칸마다 양식의 원래 글(정확히), 채울 방법(이름표 빈칸 / 안내 문구 자리 / 표 칸), 들어갈 내용 한 줄.

끝 조건: 양식의 모든 제목·표·안내 문구가 칸 지도의 어느 칸에 들어갔다.

## 2. 공고 규칙표

공고문에서 아래를 찾아 원문 줄과 함께 적는다. 공고에 없으면 「공고에 없음」이지 다른 해의 값으로 메우지 않는다.

- 분량(쪽 수·글자 수, 목차·붙임 포함 여부), 글꼴·크기 지정
- 가리기(블라인드): 가릴 것(성명·학교·직장 등)과 써도 되는 것, 가리는 표시(○·*)
- 안내 문구 지우기·글자색, 제출 파일 꼴(HWP·PDF)
- 평가 항목과 배점

PSST 목차와 그간 알려진 규칙(2차 근거)은 [references/psst.md](references/psst.md) — 공고와 다르면 공고가 이긴다.

끝 조건: 규칙표의 칸마다 공고 원문 줄이나 「공고에 없음」이 있다.

## 3. 사실표와 칸별 글

사업 자료에서 **아는 값 / 계산한 값 / 모르는 값**을 가른다. 시장 규모·성장률·경쟁사 숫자는 출처(기관·자료명·연도)가 있는 것만 쓰고, 없으면 「근거 확인 필요」로 남긴다 — 그럴듯한 숫자를 만들지 않는다. 칸마다 평가 항목 하나 이상에 답하게 쓰고, 분량을 칸별로 나눠 상한 안에 둔다. 표가 있는 칸은 표로, 서술 칸은 개조식(□·○·-) 양식이면 그 꼴을 그대로 따른다.

끝 조건: 칸 지도의 모든 칸에 들어갈 글이 있고, 모든 숫자에 출처나 계산이 붙었다.

## 4. 채우기 — 양식 서식 그대로

도구별로 되는 것과 안 되는 것은 [references/form-tools.md](references/form-tools.md)(직접 돌려 확인한 사실).

- 이름표 빈칸(과제명·대표자 등): `fill-hwp 양식.hwpx --values '{"과제명":"…"}' --output 결과.hwpx`. 같은 이름표가 여러 칸이면 배열이나 더 긴 이름표로.
- 안내 문구·자리표시 자리: `edit-hwp 결과.hwpx --replacements "$TMPDIR/바꿀글.json"` 로 **그 줄을 본문으로 바꿔 쓴다**. 안내 문구만 지우는 것(빈 글로 바꾸기)은 엔진이 거절한다 — 그 자리에 본문을 넣는다.
- 양식에 문단·표 줄이 모자라면(edit-hwp 는 새 문단·새 표 줄을 만들지 않음) 사람에게 고르게 한다: 한 문단에 모아 쓰기 / 한글 프로그램에서 직접 늘리기 / 양식 글로 새 HWPX 만들기(양식 서식이 바뀜).
- HWP(옛 형식) 양식은 채우면 같은 내용의 새 HWPX 가 된다(`formattingPreserved: false`). 이 사실과 제출 꼴이 HWP 인지를 사람에게 알린다.
- DOCX 양식은 `edit-docx`(`label`·`find/replace`·`appendRow`·`appendParagraph` 의 `after`).

끝 조건: 도구 결과에 `stillEmpty`·`missingAfterReopen`·`skipped` 가 비었거나, 남은 것을 사람에게 알릴 목록으로 적었다.

## 5. 검사

```bash
"$T5_DOCUMENT_CLI" read-hwp "결과.hwpx" > "$TMPDIR/결과.json"
node "${CLAUDE_SKILL_DIR}/scripts/proposal.mjs" check --input "$TMPDIR/결과.json" --mask "대표자이름,학교,직장"
```

공고가 글자 수 상한을 두면 `--max-chars N` 을 더한다. `--mask` 에는 2단계 규칙표가 가리라는 실제 말(사람 이름·학교·직장)을 넣는다. 출력의 `problems` 가 검사의 전부다: 남은 안내 문구·자리표시, 빈 표 칸, 가릴 말 노출, 학교 이름 후보, PSST 순서, 글자 수 초과. 고치고 한 번 더 검사하고, 맴돌지 않는다. 신청서·이름표 칸처럼 이름을 적어야 하는 자리의 노출은 공고 규칙으로 판단한다.

**쪽 수**는 이 검사가 재지 못한다. 공고에 쪽 수 상한이 있으면 attachment `convert_to_pdf` 로 결과의 쪽 수를 재고, 못 재면 「쪽 수 미측정」으로 답에 적는다.

끝 조건: `problems` 가 비었거나 남은 것마다 이유가 있고, 쪽 수를 쟀거나 미측정으로 적었다.

## 6. 평가 대조표와 답

평가 항목마다 「어느 칸 어느 문장이 답하는가」를 한 줄씩 표로 만들어 답에 붙인다(빈 항목이 보이면 그 칸을 보강). 답에는 결과 파일, 칸 지도에서 못 채운 칸, 「근거 확인 필요」 숫자, 가리기 판단, 쪽 수, 서식이 바뀐 곳(HWP→HWPX 등)을 적는다. 제출은 사람이 한다.

### 현재 결과판의 확인
사용자 목적과 현재 편집판/선택 레퍼런스의 원리를 필요한 범위만 적용한다. 이미 읽은 방법을 다시 열거나 국소 수정에 전체 조사를 반복하지 않는다. 기존 제작·내용·렌더 검사의 이름/범위/근거를 전달할 attachment/family/판/SHA와 결속한다(프로젝트·렌더판이 있으면 함께). 같은 바이트의 유효 검수는 재사용하고, 바뀐 부분은 확인을 갱신한다. 모델의 체크리스트·일반 파일 등록·기계 검사·사람의 품질 평가는 서로 대신하지 않는다. 원본과 승인된 부분은 보존하며 확인하지 못한 범위는 미측정으로 남긴다.
