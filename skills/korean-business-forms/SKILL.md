# 한국 업무 서식

받는 거래처가 그대로 받아 결재·입금할 수 있는 한 장을 만든다. 금액 한 원, 칸 하나가 틀리면 다시 보내야 하니 **계산과 칸은 스크립트가, 문장과 판단은 모델이** 맡는다.
아래는 규칙이 아니라 원리다. 사람의 말·「내 방식」·전에 쓰던 서식이 있으면 그것이 먼저다. **거래처·관공서가 준 양식 파일이 있으면 새로 만들지 않고 그 양식을 채운다**(`document-data` 의 `fill-hwp`·`edit-docx`·`edit-xlsx`) — 이 방법은 계산(2단계)과 표기(4단계 원리)만 빌려 준다.

## 0. 서식과 파일 정하기

| 서식 | 기본 파일 | 만드는 길 |
|---|---|---|
| 견적서·청구서 | 워드(DOCX) — 엑셀을 말하면 XLSX | 2~3단계 |
| 거래명세서 | 엑셀(XLSX) — 워드를 말하면 DOCX | 2~3단계 |
| 용역·행사·납품 계약서 | 워드(DOCX) | 4단계 |
| 공문(기안문·시행문) | 한글(HWPX) | 5단계 |

영수증·발주서처럼 표에 없는 서식은 가장 가까운 꼴(발주서는 견적서의 공급자·공급받는자를 뒤집은 꼴)로 만들고, 그 사실을 답에 적는다. 칸마다 무엇이 법정 근거이고 무엇이 관행인지는 [references/form-facts.md](references/form-facts.md).

끝 조건: 서식, 파일 꼴, 결과 파일 이름이 정해졌다.

## 1. 사실표

사람의 자료·「내 방식」·기억·전에 보낸 같은 서식에서 값을 모아 `"$TMPDIR"/사실.json` 에 쓴다(칸 이름과 꼴은 form-facts.md 1절). 숫자·이름·번호는 사실표에서만 온다.

- 모르는 칸은 지어내지 않고 비워 둔다. 스크립트가 「(미정)」으로 적고 `missing` 에 올린다.
- **단가가 부가세 포함인지**(`priceIncludesVat`)는 합계를 10% 바꾼다. 자료에 없으면 이것 하나는 묻는다.
- 끝수 처리(기본: 원 미만 버림)와 세액을 품목마다 낼지(기본) 합계에서 한 번 낼지는 사람·전 서식이 정한 것을 따른다.

끝 조건: 사실표 파일이 있고, 부가세 포함 여부가 정해졌다.

## 2. 계산과 틀 — 스크립트 한 번

```bash
node "${CLAUDE_SKILL_DIR}/scripts/forms.mjs" build --facts "$TMPDIR/사실.json" --format docx --out "$TMPDIR/명세.json"
```

`--format xlsx` 면 엑셀 명세(공급가액·세액·합계가 수식으로 남고 값도 함께 실림)다. 출력은 `totals`(공급가액·세액·합계·한글 금액), `missing`, `warnings`, 다음 명령이다. 금액과 한글 금액은 이 계산만 쓰고 손으로 다시 셈하지 않는다. `warnings` 의 사업자등록번호 「확인 필요」는 원본과 대조할 일이지 막을 일이 아니다.

한글 금액만 필요하면 `forms.mjs amount 113560`, 번호 확인만 필요하면 `forms.mjs bizno 123-45-67890`.

끝 조건: 명세 파일이 있고 `missing` 을 사람에게 묻거나 「(미정) 초안」으로 넘길지 정했다(거래처에 바로 보낼 결과면 묻는다).

## 3. 만들기 — 문서 도구 한 번

```bash
"$T5_DOCUMENT_CLI" create-docx --spec "$TMPDIR/명세.json" --output "견적서_가나다_20261026.docx"
```

엑셀은 `create-xlsx`. 결과 파일을 `local_change` 대상으로 선언하는 것, 다시 읽은 글이 검사라는 것, 넘기는 법은 `document-data` 와 같다. 다시 읽은 글에서 셋만 대조한다: 합계 금액 숫자 = `totals.total`, 한글 금액 = `totals.totalHangul`, 「(미정)」 개수 = `missing` 개수. 한 쪽짜리 서식이라 화면 렌더 점검은 사람이 모양을 문제 삼을 때만 한다.

직인·로고는 사람이 준 그림만 `edit-docx` 의 `insertImage` 로 넣는다(만들어 그리지 않는다).

끝 조건: 결과 파일이 다시 열렸고 위 세 대조가 맞는다.

## 4. 계약서 — 견적과 같은 금액

견적서를 만든 사실표에 계약 칸을 더해 그대로 쓴다(꼴과 유형별 꼭 들어갈 조항은 [references/contracts.md](references/contracts.md)). 조항 문장은 사람의 말·전에 쓰던 계약서·견적 조건에서 가져와 `clauses` 에 쓴다.

```bash
node "${CLAUDE_SKILL_DIR}/scripts/forms.mjs" contract --facts "$TMPDIR/계약.json" --out "$TMPDIR/계약명세.json"
"$T5_DOCUMENT_CLI" create-docx --spec "$TMPDIR/계약명세.json" --output "용역계약서_가나다_20261026.docx"
```

계약 금액은 견적과 같은 계산이라 견적서와 한 원도 다르지 않다. `missing` 에 빠진 조항(문화예술용역·하도급 납품은 법정 항목), 지급 일정 합계가 계약 금액과 다름이 나온다. 빈 조항은 사람에게 묻는다 — 지어내지 않는다. 조항이 유리한지 불리한지는 판단하지 않고, 그런 질문에는 전문가 확인을 권한다. 거래처·기관이 준 계약서 양식이 있으면 그 양식을 `edit-docx`·`fill-hwp` 로 채운다.

끝 조건: `missing` 이 비었고 다시 읽은 글의 계약 금액이 `totals.total` 과 같다.

## 5. 공문 — 한글 기안문 꼴

[templates/gongmun-gian.md](templates/gongmun-gian.md) 꼴로 마크다운을 쓰고 한 번에 만든다.

```bash
"$T5_DOCUMENT_CLI" create-hwpx --markdown "$TMPDIR/공문.md" --preset 기안문 --output "공문_단가조정_20261026.hwpx"
```

- 항목은 마크다운 번호 목록을 들여 써서 단계를 나타낸다. 엔진이 `1.` → `가.` → `1)` 로 바꾸므로 기호를 손으로 쓰지 않는다.
- 날짜 `2026. 10. 26.`(일 뒤 마침표까지), 시간 `14:30`(24시각), 숫자는 아라비아 숫자. 근거와 확인 정도는 [references/notation.md](references/notation.md).
- 「끝.」은 엔진이 문서 맨 끝에 붙인다. 직접 쓰면 두 번 찍힌다. 그래서 마지막 문단은 붙임(없으면 본문 마지막 항목)으로 두고, 발신 명의는 맨 위 `#` 줄에 쓴다. 결문(시행 번호·주소·연락처)이 필요하면 붙임 뒤에 두 칸 표로 두되, 그러면 「끝.」이 표 뒤로 간다는 것을 답에 적는다.
- 관공서가 정한 공문 양식(HWPX)을 받았으면 이 틀 대신 그 양식을 `fill-hwp`·`edit-hwp` 로 채운다.

끝 조건: 다시 읽은 글에 항목 기호가 차례대로 있고 「끝.」이 한 번만 있다.

## 6. 답

결과 파일, 합계 금액(숫자와 한글), 끝수 처리·세액 기준, 「(미정)」 칸, 확인이 필요한 번호를 적는다. 「세금계산서로 끊어 줘」라는 부탁이면 법정 기재사항 4칸이 사실표에 다 있는지만 알려 주고, 발급은 홈택스 길로 넘긴다(form-facts.md 4절).

### 현재 결과판의 확인
사용자 목적과 현재 편집판/선택 레퍼런스의 원리를 필요한 범위만 적용한다. 이미 읽은 방법을 다시 열거나 국소 수정에 전체 조사를 반복하지 않는다. 기존 제작·내용·렌더 검사의 이름/범위/근거를 전달할 attachment/family/판/SHA와 결속한다(프로젝트·렌더판이 있으면 함께). 같은 바이트의 유효 검수는 재사용하고, 바뀐 부분은 확인을 갱신한다. 모델의 체크리스트·일반 파일 등록·기계 검사·사람의 품질 평가는 서로 대신하지 않는다. 원본과 승인된 부분은 보존하며 확인하지 못한 범위는 미측정으로 남긴다.
