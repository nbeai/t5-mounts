# 티파이브 장착 창고

**한국형 AI 비서 티파이브**에서 잘 작동하도록 우리가 직접 만들거나, 남이 만든 것을 검수·손본 기능을 모아 둔 곳입니다. 여기 있는 기능은 티파이브에 그대로 넣어 바로 쓸 수 있습니다.

- 공식 안내: https://t5.beai.kr/
- 넣을 수 있는 것: **작업 방법(스킬)**, **플러그인 묶음**, **연결(MCP 서버)**, **프로그램(CLI)**. 자동 실행(훅)은 티파이브에 그 기능이 생긴 뒤에 넣습니다.

> 지금은 준비 중입니다. 첫 항목이 검수 중이고, 아직 공개하지 않았습니다(라이선스·공개 시점은 오너 결정 대기).

## 설치하는 법

티파이브 대화창에서 말로 합니다. 따로 배울 것은 없습니다.

1. **파일로 받은 경우** — 받은 zip 파일을 대화창에 붙이고 「**이 파일로 기능 추가해 줘**」라고 말합니다.
2. **주소로 넣는 경우** — 아래 항목 목록의 주소를 붙이고 「**이 기능 쓰고 싶어**」라고 말합니다. 꼭 항목 하나의 주소(`…/tree/<판>/skills/<이름>`)를 붙여 주세요. 창고 첫 주소를 붙이면 들어 있는 것이 한꺼번에 들어갑니다.
3. 티파이브가 들이기 전에 그 기능이 **컴퓨터에서 프로그램을 실행하는지, 어느 사이트에 접속하는지**를 한 번 알려 줍니다.
4. 들어온 기능은 **설정 › 장착 목록**에 보이고, 거기서 끄기·켜기·빼기를 할 수 있습니다.

나중에는 티파이브 설정의 「장착 진열대」에서 이 창고의 목록을 바로 보고 한 번 눌러 설치하게 됩니다(준비 중).

## 안전 장치

- **검수 증명서** — 항목마다 `mount.json` 이 있습니다. 누가 만들었는지, 원본이 어디 있고 어느 판으로 고정했는지, 어떤 파일이 들어 있는지(파일마다 지문), 라이선스, 쓰는 권한(파일·프로그램 실행·인터넷·외부 전송·돈), 맥·Windows 확인 여부, 언제 무엇을 어떻게 확인했는지가 적혀 있습니다. 확인 규칙은 [CHECKLIST.md](CHECKLIST.md).
- **서명된 목록** — 모든 증명서를 모은 `index.json` 에 전자 서명(`index.sig`, Ed25519)이 붙어 있습니다. 누가 목록이나 파일을 몰래 바꾸면 서명·지문이 맞지 않게 됩니다. 지금은 이 창고의 검증 도구가 확인하고, 장착 진열대가 생기면 티파이브가 설치 전에 같은 확인을 합니다. 서명 확인 열쇠는 `keys/t5-mounts-public.pem` 입니다.
- **남이 만든 것은 원본을 가리키기만** — 외부 연결·프로그램은 원본 코드를 이 창고에 복사하지 않고, 원래 주소와 고정한 판만 적어 둡니다. 우리 창고에는 티파이브에 붙이는 얇은 설정과 검수 기록만 있습니다.
- **비밀값 0** — 키·비밀번호는 이 창고 어디에도 없습니다. 키가 필요한 기능은 사용자가 티파이브의 키 입력 칸에 직접 넣습니다.
- 티파이브가 사용자에게 멈춰 묻는 일(백업 없는 지우기·돈이 나가는 일)을 몰래 건너뛰는 기능은 넣지 않습니다.

## 관리하는 사람을 위한 안내

필요한 것: Node 20 이상(의존성 없음).

```bash
node tools/validate.mjs
```

| 명령 | 하는 일 |
|---|---|
| `node tools/validate.mjs` | 모든 `mount.json` 을 스키마(`schema/mount.schema.json`)와 실제 파일 지문으로 검사 |
| `node tools/refresh-files.mjs <항목 폴더>` | 파일을 바꾼 뒤 그 항목의 파일 지문을 다시 적음(검수를 대신하지 않음) |
| `node tools/build-index.mjs` | 검사를 통과한 항목으로 `index.json` 을 만듦 |
| `node tools/sign-index.mjs --key <저장소 밖 비밀 열쇠>` | `index.json` 에 서명해 `index.sig` 를 씀 |
| `node tools/verify.mjs` | 항목 검사 + 목록이 지금 항목과 같은가 + 서명 확인 |
| `node --test test/*.test.mjs` | 서명 틀림·지문 틀림·항목 빠짐 등을 잡는지 시험 |

**지금 서명은 시험 열쇠로 한 것입니다**(열쇠 번호 `132ced345b8f7f47`). 진짜 열쇠는 오너가 만들고 새 판 알림과 같은 열쇠를 씁니다. **오너 열쇠로 다시 서명하는 법(한 줄):**

```bash
node tools/keygen.mjs --out <저장소 밖 안전한 폴더> --install-public && node tools/build-index.mjs && node tools/sign-index.mjs --key <그 폴더>/t5-mounts-private.pem && node tools/verify.mjs
```

이미 만든 열쇠가 있으면 [keys/README.md](keys/README.md) 의 방법을 따릅니다. 비밀 열쇠는 이 저장소 안에 두지 않습니다(도구가 저장소 안 경로를 거절하고, `.gitignore` 가 `*.pem` 을 막습니다).

폴더: `skills/`(작업 방법) · `plugins/`(플러그인 묶음) · `mcp/`(연결) · `cli/`(프로그램) · `hooks/`(자동 실행 — 자리만) · `schema/` · `tools/` · `test/` · `keys/`.
